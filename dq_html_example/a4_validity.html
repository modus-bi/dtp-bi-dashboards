Validity = соответствие значения формату/диапазону/справочнику. Для адресного реестра у нас 3 типа проверок: regex (UUID, KLADR, кадастровый номер), range (даты, числа), enum (status, obj_type, sostad).

1. Regex-валидация идентификаторов

SELECT 'n_fias_uuid_v4' AS rule, COUNT(*) AS not_null,
  COUNT(*) FILTER (WHERE n_fias !~ '^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-...$') AS invalid
FROM mos.address_reestr WHERE n_fias IS NOT NULL AND n_fias <> '';

-- KLADR может быть 13 (улица) или 17 (дом) цифр
SELECT 'kladr_13_or_17_pattern' AS rule, COUNT(*),
  COUNT(*) FILTER (WHERE kladr !~ '^[0-9]{13}$' AND kladr !~ '^[0-9]{17}$')
FROM mos.address_reestr WHERE kladr IS NOT NULL AND kladr <> '';

-- кадастровый номер: NN:NN:NNNNNN(N):NN
SELECT 'kad_n_pattern', COUNT(*),
  COUNT(*) FILTER (WHERE kad_n !~ '^[0-9]{1,2}:[0-9]{1,2}:[0-9]{6,7}:[0-9]+$')
FROM mos.address_reestr WHERE kad_n IS NOT NULL AND kad_n <> '';

Анти-паттерн в первой попытке. Изначально мы написали kladr ~ '^[0-9]{17}$' (только 17-значный) и получили 15.89% невалидов. Это ложно-положительный результат — 13-значный код тоже валиден (это уровень улицы). После уточнения regex до '^[0-9]{13}$|^[0-9]{17}$' процент упал до 0%.

Урок: прежде чем объявлять «низкое качество», изучи стандарт справочника. KLADR — это код переменной длины, и оба варианта легитимны.

2. Range-валидация дат

SELECT EXTRACT(YEAR FROM d_fias)::int AS yr, COUNT(*) AS n
FROM mos.address_reestr
WHERE d_fias < '1990-01-01' OR d_fias > '2026-12-31'
GROUP BY yr ORDER BY yr;
ГодЗаписейИнтерпретация
1753129🔴 явный sentinel — реалистичной даты ввода в ФИАС в 1753 году нет
1900-01-016 215🟠 типичный sentinel «дата неизвестна» (Excel epoch+0)

Итого 6 344 записи с суррогатной датой = 1.46% от 435 294 не-NULL значений d_fias. Это много для исторического поля, но мало для общего рейтинга качества.

Sentinel-даты — частый паттерн. Когда система не знает реальную дату, разработчик ставит «безопасный» placeholder: 1900-01-01 (Excel-наследие), 1970-01-01 (Unix epoch), 1753-01-01 (минимум SQL Server datetime), 9999-12-31 (для «никогда»). Все они проходят validity (это валидная дата), но семантически = NULL. Хорошее DQ-правило ловит их явно.

Найдены 2 типичные DQ-беды:
  • Sentinel-значения -: 8 988 в status + 9 773 в sostad. Это «не пустое» (проходит NOT NULL), но «не значение» (не несёт информации). Семантически = unknown.
