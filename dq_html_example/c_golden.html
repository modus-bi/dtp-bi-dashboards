В A-этапе мы нашли «грязные» значения: ё-варианты улиц, sentinel-«-», typo «ожидает аннулирование». Этап C создаёт канонический слой — справочники с правильными значениями и view-обёртку, которая преобразует raw → canonical в одном месте.

2. golden_yo_streets — каноническое написание Ё

CREATE TABLE IF NOT EXISTS mos.golden_yo_streets (
  canonical     text PRIMARY KEY,       -- 'Берёзовая улица'
  variant_no_yo text NOT NULL,          -- 'Березовая улица'
  is_canonical_with_yo boolean DEFAULT true
);

View-обёртка: address_reestr_canonical

CREATE OR REPLACE VIEW mos.address_reestr_canonical AS
SELECT
  ar.global_id, ar.unom, ar.n_fias, ar.kad_n, ar.kladr,
  ar.address, ar.simple_address, ar.adm_area,
  ga.short_name AS adm_area_code,
  ar.district,
  -- p7: канонизация ё/е
  COALESCE(g_yo.canonical, ar.p7) AS p7_canonical,
  ar.p7 AS p7_raw,
  -- status: typo→canonical
  COALESCE(g_typo.canonical, ar.status) AS status_canonical,
  ar.status AS status_raw,
  ar.sostad, ar.obj_type, ar.d_fias, ar.dreg, ar.ddoc, ar.loaded_at,
  -- DQ-флаги
  (ar.status = '-')                        AS has_sentinel_status,
  (ar.sostad = '-')                        AS has_sentinel_sostad,
  (ar.d_fias < '1990-01-01')               AS has_sentinel_date,
  (ar.p7 IN (SELECT variant_no_yo FROM mos.golden_yo_streets)) AS has_yo_typo,
  (ar.obj_type = 'Здание' AND ar.status = 'Внесён в ГКН'
   AND (ar.kad_n IS NULL OR ar.kad_n = ''))  AS missing_kadn_for_building
FROM mos.address_reestr ar
LEFT JOIN mos.golden_adm_areas    ga    ON ga.adm_area = ar.adm_area
LEFT JOIN mos.golden_yo_streets   g_yo  ON g_yo.variant_no_yo = ar.p7
LEFT JOIN mos.golden_status_typo  g_typo ON g_typo.raw = ar.status;

Польза golden-слоя:
  • Дашборды читают address_reestr_canonical и группируют по уже канонизованным значениям — не надо в каждом запросе писать CASE WHEN p7 IN (...) THEN ....
  • В B-этапе при изменении правил можно добавлять новые DQ-флаги в одном месте (view), не трогая 21 INSERT-запрос.
  • Список «всех проблемных строк» = SELECT * FROM ... WHERE any_issue — основа для report incident feed.
