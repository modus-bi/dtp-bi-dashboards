В A.3 мы нашли точные дубликаты по полям. Теперь ищем почти-дубликаты — записи, которые отличаются лишь буквой Ё, регистром или одной цифрой. Postgres даёт два инструмента: pg_trgm (триграмное сходство) и fuzzystrmatch.levenshtein.

1. Exact duplicates по simple_address

SELECT simple_address, COUNT(*) AS dup
FROM mos.address_reestr
WHERE simple_address IS NOT NULL AND simple_address <> ''
GROUP BY simple_address HAVING COUNT(*) > 1
ORDER BY dup DESC LIMIT 15;

2. Yo-варианты улиц (Е/Ё) — реальная DQ-проблема

WITH norm AS (
  SELECT p7, LOWER(translate(p7, 'ёЁ', 'еЕ')) AS canonical
  FROM mos.address_reestr
  WHERE p7 IS NOT NULL AND p7 <> ''
  GROUP BY p7
)
SELECT canonical, array_agg(p7 ORDER BY p7) AS variants, COUNT(*) AS n
FROM norm
GROUP BY canonical HAVING COUNT(*) > 1;

Серьёзная проблема. Для «Озёрная улица» правильный вариант (с ё) имеет 1 452 объекта, а вариант без ё — только 2. Это typo-кейс: при ручном вводе кто-то набрал «Озерная» вместо «Озёрная». Эти 2 объекта не находятся при поиске «Озёрная», даже если оператор ищет ту же улицу.

Для дашборда DQ это must-show: «3 улицы с разной транслитерацией Ё → 1 736 объектов под одним из вариантов, 282 под другим».

3. pg_trgm similarity (триграммное сходство)

SET pg_trgm.similarity_threshold = 0.92;

WITH cand AS (
  SELECT global_id, simple_address
  FROM mos.address_reestr WHERE p7 = 'Озёрная улица'
)
SELECT a.simple_address, b.simple_address,
       round(similarity(a.simple_address, b.simple_address)::numeric, 3) AS sim
FROM cand a
JOIN cand b ON a.simple_address % b.simple_address  -- триграммный оператор
            AND a.global_id < b.global_id
            AND a.simple_address <> b.simple_address
ORDER BY sim DESC LIMIT 10;
Ловушка триграмм. Для коротких различий вроде «дом 19, корпус 1, строение 2» vs «дом 19, корпус 2, строение 1» pg_trgm возвращает sim=1.000, потому что все триграммы совпадают (только порядок цифр меняется). На длинных строках разница в 1–2 символах теряется. pg_trgm хорош для прелуминарного отбора кандидатов, но финальное решение должен принимать другой алгоритм (Levenshtein или семантический parser).

4. Levenshtein — точное расстояние редактирования

WITH cand AS (
  SELECT global_id, simple_address, length(simple_address) AS L
  FROM mos.address_reestr WHERE p7 = 'Берёзовая улица'
)
SELECT a.simple_address, b.simple_address,
       levenshtein(a.simple_address, b.simple_address) AS dist
FROM cand a JOIN cand b ON a.global_id < b.global_id
WHERE abs(a.L - b.L) <= 3
  AND levenshtein(a.simple_address, b.simple_address) BETWEEN 1 AND 3
ORDER BY dist LIMIT 10;

Levenshtein без нормализации даёт ложные срабатывания. «дом 3» и «дом 4» — это разные дома, расстояние 1 не означает дубликат. Правильный пайплайн:
  1. Нормализовать: убрать различия чисел, привести регистр.
  2. Levenshtein по текстовой части, не по числам.
  3. Threshold: dist ≤ 2 при maxlen ≥ 30 ⇒ возможный дубликат.
