Адресный реестр — комбинация трёх справочников: городского (UNOM), федерального ФИАС (n_fias) и кадастрового (kad_n). У каждого свои правила уникальности; реальность всегда чуть хуже.

SQL запрос

WITH stats AS (
  SELECT
    COUNT(*)                       AS total_rows,
    COUNT(DISTINCT unom)           AS distinct_unom,
    COUNT(DISTINCT n_fias)         AS distinct_n_fias,
    COUNT(DISTINCT kad_n)          AS distinct_kad_n,
    COUNT(DISTINCT kladr)          AS distinct_kladr,
    COUNT(DISTINCT simple_address) AS distinct_simple_address,
    COUNT(DISTINCT global_id)      AS distinct_global_id,
    COUNT(unom)                    AS notnull_unom,
    COUNT(n_fias)                  AS notnull_n_fias,
    COUNT(kad_n)                   AS notnull_kad_n
  FROM mos.address_reestr
)
SELECT * FROM stats;

Подсказка про KLADR. 1.46% уникальности у kladr — это не проблема. KLADR — это код улицы (или дома); многие здания на одной улице будут иметь один и тот же 13-значный код. Distinct=8 070 — это число улиц/локаций Москвы. Вот почему важно разделять «поля-идентификаторы» и «поля-категории»: к ним применяются разные правила.

Дубликаты UNOM (по идее должно быть 0)

SELECT unom, COUNT(*), array_agg(DISTINCT obj_type), array_agg(DISTINCT status)
FROM mos.address_reestr
WHERE unom IS NOT NULL
GROUP BY unom HAVING COUNT(*) > 1
ORDER BY COUNT(*) DESC LIMIT 10;

Природа дублей UNOM. 99 коллизий — два сценария:
  • Один UNOM используется для здания и для прилежащего земельного участка — это может быть осмысленно (по идее тогда должны быть разные obj_type), но в нашей выборке всё чаще одинаковый obj_type ⇒ это ошибка.
  • Исторические/пересмотренные записи: один UNOM перешёл из «Ожидает внесения в ГКН» в «Внесён», но обе строки остались.

Добавление obj_type к UNOM не разрешает все 99 коллизий — значит, есть случаи, когда у двух строк одинаковый и UNOM, и obj_type, и adm_area. Это явные кандидаты на дубли (исторические или ETL-баг).

Ключевая находка. 12 544 записей имеют n_fias = '' (пустая строка, не NULL). Это объясняет «псевдо-дубликаты» при COUNT(DISTINCT n_fias): пустая строка считается одним значением, на которое падает 12 544 строк. Уберём их — реальная уникальность ID становится:
distinct(n_fias where ≠ '') / count(where ≠ '') = 537 043 / 538 530 = 99.72%
