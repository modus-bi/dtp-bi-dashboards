# Prompt Engineering for BI: Правильные промпты для аналитики

> Skill для формулирования эффективных промптов при работе с BI через LLM

## Назначение

Используй этот skill когда нужно:
- Сформулировать запрос к AI для создания дашборда
- Попросить AI проанализировать данные
- Получить качественный вывод из графика
- Оптимизировать промпт для лучших результатов

## Анатомия хорошего промпта для BI

### Формула эффективного промпта

```
[ДЕЙСТВИЕ] [ЧТО] для [ЦЕЛЬ]:
- [Детали 1]
- [Детали 2]
- [Детали 3]

[Дополнительные требования]
```

**Пример:**
```
Создай дашборд продаж для анализа Q4:
- Датасет: sales_2024
- Метрики: выручка, маржа, количество заказов
- Разбивка: по регионам и категориям
- Период: октябрь-декабрь 2024

Стиль: корпоративная синяя тема
Формат: экспортируй в PDF
```

---

## 5 элементов качественного промпта

### 1. ЧТО (действие)

**Глаголы для BI:**
- `Создай` — новый отчёт/датасет/график
- `Покажи` — запросить данные
- `Найди` — поиск паттернов/аномалий
- `Сравни` — A vs B анализ
- `Проанализируй` — глубокий анализ с выводами
- `Спрогнозируй` — предсказание
- `Обнови` — изменить существующее
- `Экспортируй` — вывести в файл

**Примеры:**
```
"Создай дашборд продаж"
"Найди регионы с падением >10%"
"Сравни Q3 и Q4 по выручке"
```

---

### 2. ГДЕ (источник данных)

**Варианты:**
```
"из датасета sales_2024"
"из таблицы PostgreSQL dtp.accidents"
"из отчёта ID 598"
"из базы данных production"
```

**Примеры:**
```
"Покажи топ-10 клиентов из датасета sales_2024"
"Проанализируй таблицу accidents в схеме dtp"
```

**Если не знаешь название:**
```
"Покажи доступные датасеты"
"Какие таблицы есть в базе?"
"Какие поля в таблице sales?"
```

---

### 3. КАКИЕ (метрики/поля)

**Конкретизируй что именно:**
```
"Покажи выручку, маржу и количество заказов"
"Топ-10 по полю amount"
"Группировка по region и category"

-- Плохо:
"Покажи данные" (что именно?)
"Все метрики" (слишком общо)
```

**Для агрегации уточняй:**
```
"Сумма выручки" (SUM)
"Среднее время доставки" (AVG)
"Количество уникальных клиентов" (COUNT DISTINCT)
"Максимальный чек" (MAX)
```

---

### 4. КАК (группировка, сортировка)

**Группировка:**
```
"по регионам"
"по месяцам"
"по категориям товаров"
"по часам суток"
```

**Сортировка:**
```
"сортировка по убыванию выручки"
"в хронологическом порядке"
"топ-10 (лучшие первыми)"
```

**Фильтрация:**
```
"только активные клиенты"
"где продажи >1M"
"регионы с падением >10%"
```

---

### 5. КОГДА (период)

**Всегда указывай период:**
```
"за Q4 2024"
"последние 12 месяцев"
"с 1 января 2024"
"декабрь 2024"

-- Плохо:
"продажи" (за какой период?)
```

**Для сравнений:**
```
"Q4 2024 vs Q4 2023"
"этот месяц vs прошлый месяц"
"текущий год vs прошлый год"
```

## Примеры промптов: от простых к сложным

### Level 1: Простые запросы (данные)

```
"Покажи все данные из датасета sales_2024"

"Топ-10 клиентов по выручке"

"Продажи по месяцам за 2024"

"Количество заказов по регионам"
```

**Что AI сделает:**
- Выполнит простой SQL
- Вернёт таблицу с данными

---

### Level 2: Запросы с фильтрацией

```
"Покажи топ-10 клиентов по выручке за Q4 2024"

"Регионы где продажи упали более чем на 10% год к году"

"Товары с маржой менее 15%"

"Заказы со статусом 'отменён' за последний месяц"
```

**Что AI сделает:**
- SQL с WHERE
- Фильтрация по условиям
- Правильная агрегация

---

### Level 3: Создание визуализации

```
"Построй столбчатую диаграмму продаж по регионам за 2024"

"Создай линейный график динамики выручки по месяцам"

"Сделай круговую диаграмму распределения категорий"

"Добавь таблицу с деталями по менеджерам"
```

**Что AI сделает:**
- Создаст датасет (если нужно)
- Добавит компонент правильного типа
- Настроит category_field и value_field

---

### Level 4: Создание дашборда (комплексно)

```
"Создай дашборд продаж за Q4 2024:
- KPI панель: выручка, маржа, количество заказов
- Линейный график динамики по месяцам
- Столбчатая диаграмма топ-10 регионов
- Таблица деталей по менеджерам (топ-20)

Стиль: синяя корпоративная тема"
```

**Что AI сделает:**
- Создаст отчёт
- Добавит 4 компонента
- Применит стили
- Автоматически расположит (layout)

---

### Level 5: Анализ с выводами (продвинуто)

```
"Проанализируй почему продажи упали в Q3:

1. Проверь по регионам (где упало больше всего)
2. Проверь по категориям (какие товары)
3. Проверь по менеджерам (кто недовыполнил)
4. Найди корреляции с внешними факторами

Построй дашборд с выводами и рекомендациями"
```

**Что AI сделает:**
- Выполнит 4 анализа (SQL запросы)
- Создаст дашборд с графиками
- Сформулирует выводы (root cause)
- Даст рекомендации (что делать)

## Антипаттерны промптов

### Слишком общий промпт

**Плохо:**
```
"Покажи данные"
"Сделай дашборд"
"Проанализируй"
```

**Проблема:** AI не знает ЧТО именно показать.

**Хорошо:**
```
"Покажи топ-10 клиентов по выручке за 2024"
"Создай дашборд продаж с KPI и графиками"
"Проанализируй корреляцию доставки и NPS"
```

---

### Неоднозначность

**Плохо:**
```
"Покажи продажи"
```

**Вопросы:**
- Какие продажи? (gross? net? по регионам?)
- За какой период? (день? месяц? год?)
- В каком виде? (таблица? график?)

**Хорошо:**
```
"Покажи сумму продаж (gross) по регионам за Q4 2024
в виде столбчатой диаграммы"
```

---

### Противоречивые требования

**Плохо:**
```
"Создай pie chart с топ-20 категориями"
```

**Проблема:** Pie chart нечитаем с 20 сегментами!

**Решение:**
```
AI должен предложить:
"Pie chart лучше работает с 5-7 категориями.
 Предлагаю:
 - Топ-7 категорий
 - Остальные в 'Прочие'
 - Или использовать Bar Chart для всех 20

 Что выбираете?"
```

## Промпт-шаблоны для типовых задач

### Шаблон 1: Исследование данных

```
Проанализируй датасет [название]:
- Покажи структуру (поля, типы)
- Покажи примеры данных (первые 10 строк)
- Статистика по числовым полям (min, max, avg)
- Уникальные значения для категориальных полей
- Есть ли пропуски (NULL)?
```

---

### Шаблон 2: Топ-N анализ

```
Топ-[N] [категория] по [метрика] за [период]:
- Датасет: [название]
- Сортировка: по убыванию
- Визуализация: столбчатая диаграмма
```

**Пример:**
```
Топ-10 регионов по выручке за 2024:
- Датасет: sales_2024
- Сортировка: по убыванию
- Визуализация: столбчатая диаграмма
```

---

### Шаблон 3: Динамика по времени

```
Динамика [метрика] по [период] за [временной промежуток]:
- Датасет: [название]
- Группировка: по [день/неделя/месяц]
- Визуализация: линейный график
- Дополнительно: [сравнение/тренд/прогноз]
```

**Пример:**
```
Динамика выручки по месяцам за 2024:
- Датасет: sales_2024
- Группировка: по месяцам
- Визуализация: линейный график
- Дополнительно: сравнение с 2023 (пунктирная линия)
```

---

### Шаблон 4: Сравнительный анализ

```
Сравни [A] vs [B] по [метрика]:
- Датасет: [название]
- Метрики: [список]
- Визуализация: [тип]
- Вывод: найди главные отличия и причины
```

**Пример:**
```
Сравни Q3 vs Q4 по выручке и марже:
- Датасет: sales_2024
- Метрики: revenue, margin, orders
- Визуализация: две линии на одном графике
- Вывод: почему Q4 лучше? Драйверы роста?
```

---

### Шаблон 5: Root Cause Analysis

```
Проанализируй причину [изменение метрики]:

Проверь гипотезы:
1. [Гипотеза 1] — [как проверить]
2. [Гипотеза 2] — [как проверить]
3. [Гипотеза 3] — [как проверить]

Для каждой:
- SQL запрос для проверки
- Визуализация
- Вывод: подтверждена или нет

Итоговый вывод: главная причина + рекомендации
```

**Пример:**
```
Проанализируй причину падения конверсии с 3.2% до 2.1%:

Проверь гипотезы:
1. Изменение цен — корреляция цена vs конверсия
2. Проблемы с оплатой — % отказов платёжной системы
3. Скорость сайта — bounce rate vs load time

Для каждой:
- SQL запрос
- График корреляции
- Вывод

Итог: что именно вызвало падение + как исправить
```

## Прогрессия сложности промптов

### Начинающий (простые данные)

```
"Покажи продажи за декабрь"
"Топ-5 клиентов"
"Сколько заказов вчера"
```

**Подходит для:** Быстрые справки, ad-hoc запросы

---

### Средний (с деталями)

```
"Создай дашборд продаж:
- KPI: выручка, маржа, заказы
- График динамики по неделям
- Топ-10 товаров"
```

**Подходит для:** Стандартные дашборды

---

### Продвинутый (с анализом)

```
"Проанализируй продажи за Q4:
- Сравни с Q3 и Q4 прошлого года
- Найди драйверы роста и зоны риска
- Построй дашборд с выводами
- Дай 3 приоритетные рекомендации с impact оценкой"
```

**Подходит для:** Глубокий анализ, бизнес-решения

---

### Эксперт (комплексные задачи)

```
"Проведи полное исследование клиентской базы:

Этап 1: Сегментация
- RFM анализ (Recency, Frequency, Monetary)
- Выдели Champions, Loyal, At Risk, Lost
- Для каждого сегмента: размер, LTV, churn risk

Этап 2: Cohort Analysis
- Когорты по месяцам регистрации
- Retention по месяцам (12 периодов)
- Найди лучшие и худшие когорты

Этап 3: Predictive
- Спрогнозируй churn для сегмента At Risk
- Оцени potential revenue loss

Этап 4: Recommendations
- Для каждого сегмента: стратегия работы
- Приоритизация (по ROI)
- Quantified impact

Результат: Executive dashboard + detailed report + action plan"
```

**Подходит для:** Стратегические исследования

## Специализированные промпты

### Для исследования данных (postgres-mcp)

```
"Исследуй таблицу [название]:
1. Покажи схему (поля, типы)
2. Покажи 10 примеров строк
3. Статистика по числовым полям
4. Топ-10 значений для категориальных полей
5. Есть ли NULL? Outliers? Дубликаты?"
```

---

### Для создания датасета (modusbi-mcp)

```
"Создай датасет [название] из таблицы [источник]:

SQL:
- Поля: [список]
- Фильтр: [условия]
- Группировка: [по чему]
- Сортировка: [как]

Semantic layer:
- Alias для полей (русские названия)
- Описания для LLM"
```

---

### Для стилизации

```
"Примени стили к отчёту [ID]:

Цвета:
- Основной: [цвет]
- Акцентный: [цвет]
- Фон: [цвет]

Типографика:
- Заголовки: [размер]px
- Текст: [размер]px

Дополнительно:
- [требования]"
```

**Примеры:**
```
"Синяя корпоративная тема"
"Для презентации (контрастные цвета)"
"Для печати (чёрно-белая)"
"Минималистичный стиль"
```

---

### Для генерации выводов

```
"Проанализируй график [название] и сформулируй вывод:

Структура вывода (обязательно!):
1. Главная метрика (1 число + контекст)
2. Драйверы роста (топ-3)
3. Зоны риска (топ-2)
4. Приоритетные действия (3 шт с дедлайнами и impact)
5. Прогноз

Стиль: деловой, конкретный, с цифрами
Формат: HTML с gradient background"
```

## Промпты для проверки гипотез

### Структура

```
"Проверь гипотезу: [утверждение]

Данные: [источник]
Метод: [корреляция/сравнение/тест]
Визуализация: [тип графика]

Вывод должен содержать:
- Подтверждена или опровергнута
- Статистическая значимость (p-value если применимо)
- Практическая значимость (effect size)
- Рекомендация на основе вывода"
```

**Примеры:**

**Гипотеза 1:**
```
"Проверь гипотезу: Снегопад увеличивает тяжесть ДТП

Данные: dtp.accidents
Метод: Сравнение AVG(injured) при снегопаде vs ясно
Визуализация: Bar chart + вывод

Вывод:
- Подтверждена/опровергнута
- Разница в % и абсолютных числах
- Рекомендация для ГИБДД"
```

**Гипотеза 2:**
```
"Проверь гипотезу: Время доставки влияет на NPS
```

## Когда НЕ работают короткие промпты

### Нужны детали если:

**1. Неоднозначность:**
```
-- Плохо:
"Покажи продажи"
   -> Gross или net? За какой период? По чему группировать?

-- Хорошо:
"Покажи gross продажи по регионам за Q4 2024"
```

**2. Нестандартная задача:**
```
-- Плохо:
"Создай дашборд"
   -> Какой именно? Для кого? С чем?

-- Хорошо:
"Создай executive dashboard: KPI + trend + top-10, для директора"
```

**3. Специфические требования:**
```
-- Плохо:
"Примени стили"
   -> Какие именно?

-- Хорошо:
"Примени: синий #1976D2, заголовки 24px, фон градиент"
```

```

```

**Промпт B (детальный):**

## Cognitive Load: не перегружай промпт

### Оптимальная длина

**Слишком короткий (<10 слов):**
```
"Дашборд продаж"
-> Много assumptions, может быть неправильно
```

**Оптимальный (20-50 слов):**
```
"Создай дашборд продаж за Q4:
KPI панель, график динамики, топ-10 регионов"
-> Достаточно деталей, не перегружен
```

**Слишком длинный (>200 слов):**
```
"Создай дашборд продаж за Q4 2024 с KPI панелью
включающей выручку (сумма всех заказов за период...),
маржу (рассчитанную как...), количество заказов...
[ещё 150 слов]"
-> AI может потерять фокус, упустить детали
```

**Правило:** 20-100 слов оптимально для большинства задач.

## Итеративное уточнение (лучшая стратегия)

### Вместо одного огромного промпта -> диалог

**Стратегия:**
```
1. Базовый промпт (создать основу)
2. Уточнение 1 (добавить детали)
3. Уточнение 2 (стилизация)
4. Уточнение 3 (финальные правки)
```

**Пример:**
```
User [1]: "Создай дашборд продаж за Q4"
AI:       [Создал базовый: KPI + график]

User [2]: "Добавь разбивку по категориям"
AI:       [Добавил pie chart категорий]

User [3]: "Добавь таблицу топ-20 клиентов"
AI:       [Добавил таблицу]

User [4]: "Синяя тема и экспорт в PDF"
AI:       [Применил стили + экспортировал]
```

**Преимущества:**
- Проще формулировать (маленькие шаги)
- Видишь результат на каждом шаге
- Легче исправить если что-то не так
- AI лучше понимает контекст

## Финальный чек-лист промпта

Перед отправкой промпта проверь:

**Clarity (ясность):**
- [ ] Понятно ЧТО нужно сделать (действие)
- [ ] Указан источник данных (датасет/таблица)
- [ ] Указаны метрики/поля
- [ ] Указан период (если применимо)

**Completeness (полнота):**
- [ ] Есть все обязательные параметры
- [ ] Указан тип визуализации (если нужна)
- [ ] Указаны требования к выводу (если нужны)

**Conciseness (краткость):**
- [ ] Нет лишних слов
- [ ] Нет повторений
- [ ] 20-100 слов (оптимально)

**Correctness (правильность):**
- [ ] Названия полей правильные
- [ ] Типы графиков подходят для данных
- [ ] Требования выполнимы
